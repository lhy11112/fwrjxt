## 2. 协议适配器设计

### 2.1 帧结构映射

通用帧格式映射：

```
二进制帧 (UDP)
┌─────────────────────┐
│ 0xA5 0x5A (起始码)  │
│ Addr_Src (1B)       │──→ 固定: 0xA0(平台)/0x10(反无系统)
│ Addr_Dst (1B)       │──→ 固定: 0x10(反无系统)/0xA0(平台)
│ Cmd (1B)            │──→ 命令码 (0x20, 0x30, 0xA4...)
│ Len (2B LE)         │──→ 参数长度 (N)
│ Payload (N Bytes)   │──→ 参数 (raw bytes 或 JSON)
│ Checksum (1B)       │──→ 累加和校验
└─────────────────────┘
```

    UploadTarget = 0x60,       // 上传探测目标信息
    RadarStare = 0x65,         // 雷达凝视目标
    
    // === 反制控制 ===
    ToggleAttack = 0x30,       // 开启/关闭设备攻击
    SetAttackMode = 0x31,      // 设置攻击模式
    SetAttackBand = 0x32,      // 设置攻击频段
    SwitchTarget = 0x64,       // 切换处置目标
    
    // === GNSS 诱骗 ===
    ToggleGnssSpoof = 0x36,     // 开启/关闭 GNSS 诱骗
    SetGnssSpoofMode = 0x37,   // 设置 GNSS 诱骗模式
    SetAzimuthSpeed = 0x38,    // 设置方位和速度
    ToggleGnssAutoLink = 0x41, // 开启/关闭 GNSS 诱骗联动
    
    // === 设备控制 ===
    SetPtzMode = 0x10,         // 设置云台控制模式
    SystemCalibrate = 0x12,    // 系统一键定位及校北

    SetWhiteList = 0xC0,       // 设置电磁白名单
    SetNoFlyZone = 0x42,       // 设置禁飞区
    SetLandingZone = 0x43,     // 设置定点迫降区

/// 帧编码器 — 将命令编码为二进制帧
pub struct CuasEncoder;

impl CuasEncoder {
    /// 编码通用请求帧（无参或单字节参数）
    pub fn encode_simple(cmd: CuasCommand, param: Option<u8>) -> Vec<u8>;
    
    /// 编码多参数帧（用于 GNSS 诱骗、禁飞区等）
    pub fn encode_multi(cmd: CuasCommand, params: &[u8]) -> Vec<u8>;
    
    /// 编码 JSON 参数帧（用于目标上报、设备列表等）
    pub fn encode_json(cmd: CuasCommand, json: &str) -> Vec<u8>;
    
    /// 计算校验和
    fn checksum(data: &[u8]) -> u8;
}

/// 帧解码器 — 解析二进制帧
pub struct CuasDecoder;

impl CuasDecoder {
    /// 从字节流中解析一帧
    pub fn decode(data: &[u8]) -> Result<CuasFrame>;
    
    /// 解析心跳返回参数
    pub fn decode_heartbeat(payload: &[u8]) -> Result<HeartbeatStatus>;
    
    /// 解析设备列表 JSON
    pub fn decode_device_list(json_str: &str) -> Result<DeviceListResponse>;
    
    /// 解析目标信息 JSON
    pub fn decode_target_info(json_str: &str) -> Result<Vec<DroneTarget>>;
    
    /// 解析标准返回帧 (0xA2)
    pub fn decode_response(data: &[u8]) -> Result<CommandResponse>;
}

## 3. 数据模型映射

### 3.1 探测目标数据映射（核心映射）

`0x60` 上传探测目标 JSON → HSimC2 `TrackedTarget`：

```
┌──────────────────────────┐      ┌──────────────────────────────┐
│ 反无人机系统(JSON字段)     │      │ HSimC2 TrackedTarget         │
├──────────────────────────┤      ├──────────────────────────────┤
│ UniqueID                 │ ──→  │ target_id (Uuid::new_v5)     │
│ TargetNo                 │ ──→  │ track_id                     │
│ Longitude, Latitude,     │ ──→  │ position (GeoPosition)       │
│   Altitude, Height       │      │                              │
│ Speed, Direction, Pitch  │ ──→  │ velocity (Velocity3D)        │
│ Timestamp                │ ──→  │ first_seen, last_update      │
│ TargetName               │ ──→  │ classification (机型映射)     │
│ DataType + FusedFlag     │ ──→  │ 溯源标记                       │
│ IsFriendly               │ ──→  │ 威胁等级 (Green/Red)         │
│ FreqOrNo                 │ ──→  │ 频谱特征 (RfSpectrum)        │
│ WiFiMAC                  │ ──→  │ 识别特征                       │
└──────────────────────────┘      └──────────────────────────────┘
```

### 3.2 设备列表映射

`0x50` 返回 JSON → HSimC2 `SensorMetadata` / `InterceptorResource`：

| 反无系统设备类型 | 映射到 HSimC2 模型 | 设备类型枚举 |
|----------------|-------------------|-------------|
| 0-主动雷达探测设备 | SensorManager → Radar | SensorType::Radar |
| 1-无线电侦测设备 | SensorManager → Rf | SensorType::Rf |
| 2-光电跟踪设备 | SensorManager → EoIr | SensorType::EoIr |
| 3-红外设备 | SensorManager → EoIr | SensorType::EoIr |
| 4-干扰设备 | ResourceManager → ElectronicJammer | ResourceType::ElectronicJammer |
| 6-诱骗设备 | ResourceManager → DecoyDrone | ResourceType::DecoyDrone |
| 8-智能控制箱 | 运维辅助设备 | 系统设备 |

### 3.3 状态数据映射

`0xA4/0xA6` 心跳状态 → HSimC2 `SystemHealth` + 告警规则：

| 心跳Bit位 | 含义 | 映射到 HSimC2 |
|-----------|------|--------------|
| Bit0 | 系统授权状态 | 授权告警事件 |
| Bit1 | 探测功能状态 | SystemHealth.active_sensors |
| Bit2 | 反制状态 | ResourceStatus (Deployed/Available) |
| Bit3 | 探测设备连接 | SensorStatus (Online/Offline) |
| Bit4 | 反制设备连接 | ResourceStatus |
| Bit5 | 无人值守模式 | 系统运行模式标记 |
| Bit6 | 诱骗设备状态 | SensorStatus (Online/Offline) |

### 4.2 CuasBridge 设计

```rust
/// HSimC2 ↔ 反无人机系统桥接器
///
/// 职责：
/// 1. 维护与反无系统的 UDP/TCP 连接
/// 2. 定时心跳轮询（3s被动 + 主动接收）
/// 3. 将 0x60 目标数据注入融合管道
/// 4. 将设备列表同步到 SensorManager
/// 5. 提供命令代理接口
pub struct CuasBridge {
    client: CuasClient,
    config: CuasConfig,
    bus: Arc<MessageBus>,
    sensor_mgr: Arc<SensorManager>,
    tracker: Arc<MultiTargetTracker>,
    state_cache: Arc<RwLock<CuasSystemState>>,
    running: Arc<AtomicBool>,
}

impl CuasBridge {
    /// 启动桥接器
    pub async fn start(&self) -> Result<()>;
    
    /// 停止桥接器
    pub async fn stop(&self) -> Result<()>;
}

// 内部任务
impl CuasBridge {
    /// 定时心跳轮询任务 (3s 间隔)
    async fn heartbeat_loop(self: Arc<Self>);
    
    /// 设备列表同步任务 (30s 间隔)
    async fn device_sync_loop(self: Arc<Self>);
    
    /// 主动上报监听任务 (0x60 目标数据, 0xA6 主动心跳, 0x54 设备状态)
    async fn listen_upload(self: Arc<Self>);
    
    /// 将 0x60 目标数据转换为 TrackedTarget 并注入融合引擎
    async fn ingest_target(&self, target: DroneTarget);
}
```

### 4.3 命令代理设计

```rust
/// 反无系统命令代理
///
/// 提供高可靠性的命令下发：

pub struct CommandProxy {

    /// 下发并忽略返回（fire-and-forget）
    pub async fn dispatch_async(&self, cmd: CuasCommand, payload: &[u8]);
    
    /// 获取命令执行记录
    pub async fn get_history(&self, count: usize) -> Vec<CommandLog>;
}

// 在 CuasBridge 中监听 0x60 上报
async fn ingest_target(&self, target: DroneTarget) -> anyhow::Result<()> {
    let now = chrono::Utc::now();
    
    // 1. 转换为 HSimC2 TrackedTarget
    let tracked = TrackedTarget {
        target_id: Uuid::new_v5(&CUAS_NAMESPACE, target.unique_id.as_bytes()),
        track_id: Uuid::new_v5(&CUAS_NAMESPACE, target.unique_id.as_bytes()),
        position: GeoPosition {
            latitude: target.latitude,
            longitude: target.longitude,
            altitude: target.altitude,
        },
        velocity: Velocity3D {
            vn: target.speed * target.direction.to_radians().cos(),
            ve: target.speed * target.direction.to_radians().sin(),
            vd: -target.pitch.to_radians().tan() * target.speed,
        },
        classification: map_drone_model(&target.target_name),
        threat_level: if target.is_friendly { ThreatLevel::Green } else { ThreatLevel::Red },
        confidence: 0.85,
        first_seen: now,
        last_update: now,
        track_history: vec![TrackPoint {
            timestamp: now,
            position: GeoPosition { ... },
            velocity: Velocity3D { ... },
        }],
    };
    
    // 2. 更新跟踪器
    self.tracker.update(vec![tracked]).await?;
    
    // 3. 广播态势
    let current = self.tracker.get_all().await?;
    self.bus.broadcast_situation(current);
    
    Ok(())
}
```

## 9. 关键风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| UDP 丢包导致命令丢失 | 反无操作失效 | 超时重试机制 + 命令确认校验 |
| JSON 解析失败（目标/设备） | 数据丢失 | 健壮的错误处理 + 格式校验 + 错误上报 |
| 目标高频上报撑爆通道 | 融合管道拥塞 | 背压控制（令牌桶限流） + 去重合并 |
| 反无系统离线 | 系统失效 | 断连检测 + 自动重连 + 告警通知 |
| 多频段干扰冲突 | 反制冲突 | 命令状态缓存 + 互斥锁控制 |
| 协议版本不兼容 | 解析失败 | 协议版本协商 + 自适应解码 |

## 10. 总结

本集成方案通过新增 `cuas-adapter` crate 和 `backend/src/cuas/` 模块，将反无人机系统以标准外部子系统形式无缝集成到 HSimC2 平台：

- **28个协议命令**全部映射为类型安全的 Rust API
- **探测数据**自动注入现有融合/跟踪/威胁评估管道
- **设备管理**与现有 SensorManager 同步
- **前端控制**通过 24 个 REST API 端点覆盖完整反无功能
- **Rust 生态发挥**：类型安全编解码、零成本抽象、Tokio 异步 UDP
- **无侵入集成**：不修改现有核心逻辑，仅扩展 AppState 和 API 路由

预计 **6周** 完成从协议适配到前端集成的全链路交付。
